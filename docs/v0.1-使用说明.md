# 三省六部工作台 v0.1 · 使用说明

装好并重启 DSH 之后，右侧多一栏「三省六部」。它是**贴着当前项目**的一本工作台账：谁在办、办到哪、交了什么，都在这里。中间仍然是原生聊天，没有第二个输入框。

## 1. 先接通，再派工

十席（丞相 / 中书 / 尚书 / 门下 / 吏户礼兵刑工）一开始都是「未接通」——只是编制，还没有会话。

1. **朝堂**页点卡片右下角的「接通」。宿主会给这一席建一个独立会话，并把卡片状态变成「空闲」。
2. 卡片本身是可点的：点已接通的卡片，中央区会切到那一席的会话。
3. 接通后，这一席才收得到派工。

「接通」做的事：建会话（或复用已有会话）→ 把会话号写进账本绑定 → 打开它。换绑不自动发生，需要显式重接，避免把两个部门串到同一个会话上。

## 2. 派一条任务

**任务**页 → 「新建」→ 填标题、目标、主责部门 → 「存为草稿」。

草稿不会自己跑，因为服务端不允许把任务直接塞进一个还没接通的部门。接下来：

- 部门已接通：在任务行上点 **「派工」**，任务会被投递到那一席的会话里，卡片变「正在运行」。
- 部门没接通：先回朝堂接通，再回来点「派工」。
- 派错了或不想跑了：点 **「取消」**。取消只改台账状态，不会删除已经发生的对话。

同一条任务重复点「派工」不会派出两份——幂等键按任务号生成，第二次会返回第一次那条记录。

## 3. 部门怎么回话

部门在自己的会话里干活，完成后回一段带前缀的契约行（宿主解析，不需要你手抄）：

```
【三省六部】{"action":"reportTaskResult","taskId":"…","report":{"summary":"…","checks":[…],"artifactRefs":[…]}}
```

收到并校验通过后，任务变「已完成」，成果进「成果」页。判定是三件事都要成立：**运行结束、报告合格、成果核验通过**。缺一件就停在「需人处理」，等你说下一步。

## 4. 成果与修订

**成果**页每行是一份交付物：

- 灰色「· 位置未核验」：只登记了路径，还没确认文件在不在。
- 红色虚线「· 文件已失效」：登记过，但磁盘上找不到了。记录还在，可以重新登记，或让主责部门补一份。
- 「第 N 版 · 修订自上一版」：这是某份成果的修订版，原始版本仍然可查。

点开一行 → 「找主责部门修改」→ 写清楚要改什么 → 「存为草稿」或「直接派工」。这会**只**给原主责部门开一条修订任务，不重跑三省。

## 5. 模型

部门模型由根插件按角色覆写，走的是 `/dept-model` 命令，不在右栏里改（右栏只显示当前生效的模型）：

```
/dept-model 工部 magpie workbuddy/deepseek-v4.1-flash 高
/dept-model list
/dept-model clear 工部
```

右栏卡片上的模型行就是它当前会用的那个；显示「跟随宿主」表示没有单独设。

## 6. 栏宽与键盘

- 拖分隔条，或在分隔条上按方向键（±16px，Shift ±64px，Home/End 到两端），宽度记在 `localStorage['sansheng.workbench.railWidth']`，范围 340–600。
- 卡片是 `role="button"`，Tab 可到，Enter / 空格打开会话。

## 7. 项目隔离

每个项目一本账：席位绑定、部门配置、任务、成果、事件都按项目分桶。切项目会重新取一次 `bootstrap`，看不到别的项目的东西。同一个目录被登记成两个项目会明确报冲突（要共用请显式传 `allowSharedRoot`）。

## 8. 出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 中央区白屏或样式崩了 | 控制台执行 `localStorage['sansheng.workbench.main']='off'`，刷新。接管被整个跳过，原生聊天照旧 |
| 右栏不出现 | `node scripts/workbench-preflight.mjs` 看 7 项自检；再确认重启是**彻底退出**而不是关窗口 |
| 派工后一直「已备好」 | 宿主没接上会话层：重启获取一次；右栏会提示「已记入台账，但暂时没有真的发出」 |
| 完全不想用了 | `node scripts/workbench-install.mjs off` 再重启 |

账本在 `%USERPROFILE%\.dsh\sansheng-liubu\workbench.json`。它是唯一事实来源，删掉等于清空工作台；Git 回退代码不会回退它。
