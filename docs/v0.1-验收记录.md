## 3. 复现步骤（真机部分）

1. 安装前端 bundle（已执行过一次，幂等）：

```bash
node scripts/workbench-install.mjs on     # 写进 profile 的 dependencies + dsh.profile.bundles + node_modules junction
node scripts/workbench-install.mjs status # 期望 installed=true, targetExists=true
node scripts/workbench-preflight.mjs      # 期望 7/7 通过：链接、入口、bundle 语法、12 条路由、账本可写
```

> `workbench-preflight.mjs` 是只读自检：不装、不改配置，只回答「重启后会不会白屏 / 路由起不起得来」。
> 它会真的创建 `%DSH_HOME%\sansheng-liubu` 目录（插件运行时本来也会建），除此之外不写任何东西。

2. **彻底退出 DSH 再启动**（托盘退出，不是关窗口）；只对新会话生效。
3. 打开任意项目会话，右侧应出现「朝堂 / 任务 / 成果」。
4. 依次验：接通一个部门 → 派一条任务 → 完成 → 在成果区点「找主责部门修改」。
5. 白屏逃生：控制台 `localStorage['sansheng.workbench.main']='off'` 后刷新，接管会被跳过。
6. 完全回退：`node scripts/workbench-install.mjs off` 再重启。

## 4. 已知限制（不含未验证项）

- **L1** 账本损坏时改名隔离（`<file>.corrupt-<时间戳>`），以空账本启动；不做自动修复。
- **L2** 成果只记引用，不复制文件；文件被删后靠 `existence:'missing'` 显示，历史不移除。
- **L3** 目录冲突只做字符串级归一（大小写、分隔符、末尾斜杠），**不解析 junction/短路径真实目标**；命中即报，不宣称隔离。
- **L4** `selectModel` 在宿主侧会连带改全局默认模型，所以派发前一律覆写并快照，不依赖全局默认。
- **L5** `cancel` 不撤回已排队的消息，取消后 FIFO 可能继续跑；因此取消只到 `cancel_requested`，等对账收口。
- **L6** 事件是只读游标 + 可重放，不做"读一次就消失"的队列；两个标签页会看到同一批事件。
- **L7** 400px 栏宽下模型名仍可能截断（三列每列约 112px），完整值在 `title` 里。
